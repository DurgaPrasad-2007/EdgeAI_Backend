# Direct PostgreSQL, SQLAlchemy, and Alembic

EdgeFleet connects directly to PostgreSQL through `DATABASE_URL`. No database vendor SDK is used. PostgreSQL remains an audit, task, identity, and retrieval store; it is not part of the AMR collision-safety loop.

## Apply migrations

From `E:\Edge AI\backend`:

```powershell
Copy-Item .env.example .env
# Set DATABASE_URL and strong unique authentication secrets in .env.
uv sync
uv run python scripts/migrate.py
# Or directly with alembic:
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000 --env-file .env
```

The URL must use SQLAlchemy's async driver form:

```env
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DATABASE?ssl=require
```

Port `6543` commonly indicates a PgBouncer transaction pool. The database module automatically uses `NullPool`, unique asyncpg statement names, and disables the prepared-statement cache for that endpoint. A true direct PostgreSQL endpoint normally uses port `5432`.

## ORM transaction rules

- Models live in `app/models.py` and use SQLAlchemy 2 typed declarative mappings.
- Every mutation uses `async_sessionmaker.begin()`, which commits on success and rolls back on exception.
- Reads use short-lived `AsyncSession` contexts.
- Runtime code does not concatenate request values into SQL.
- Production startup checks connectivity but does not create or mutate schema. Alembic owns schema changes.
- SQLite schema creation exists only for isolated tests.

## Authentication

The API maintains users in PostgreSQL. Passwords are Argon2 hashes; plaintext passwords are never stored. The bootstrap administrator is created only when both bootstrap variables are present and no account with that email exists.

```env
JWT_SECRET=at-least-32-random-bytes-from-a-secret-manager
JWT_ISSUER=edgefleet-api
JWT_AUDIENCE=edgefleet-console
ACCESS_TOKEN_MINUTES=15
BOOTSTRAP_ADMIN_EMAIL=admin@edgefleet.local
BOOTSTRAP_ADMIN_PASSWORD=a-strong-one-time-bootstrap-password
```

After first production provisioning, remove the bootstrap password from the environment and restart. The frontend exchanges credentials at `POST /api/auth/token`, keeps the short-lived access token in `sessionStorage`, and loads the current database-backed role from `GET /api/auth/me`.

## Migration workflow

```powershell
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
uv run alembic current
```

Review autogenerated migrations before applying them. Back up production data, test upgrade and downgrade behavior on staging, and never run destructive downgrades automatically.
